# AI朝廷 GUI — 多Agent协作剧本

## 🎯 任务
给AI朝廷做一个Web管理后台：查看各部门状态、分配任务、看对话记录、监控token用量。
这个需求天然需要多部门协作，是拍摄PR内容的理想场景。

---

## 🎬 触发策略

### 核心消息（23:00发出）
> @everyone 
> 朕决定给朝廷做一个Web管理后台，方便日常管理。
> 
> 核心需求：
> 1. 各部门状态一目了然（在线/忙碌/离线）
> 2. 能直接在界面分配任务给各部门
> 3. 查看各部门的历史对话
> 4. token消耗和成本追踪
> 
> 工部牵头技术方案，其余各部从本部职能角度提建议和需求。
> 明早朕要看完整方案。开始。

### 为什么这条消息能触发好的协作
- @everyone 让所有部门同时收到，不是一对一
- "从本部职能角度提建议" 明确邀请跨部门参与
- "明早要看" 制造紧迫感，AI会立刻开始
- 需求涉及多个领域：前端/后端/数据/安全/UX，天然触发分工

## 🛠️ GUI功能规划

### MVP（一晚能做出的）
- 📊 部门状态面板：6个部门卡片，显示在线状态和最后活跃时间
- 📝 快捷任务面板：选部门 → 输入任务 → 发送（等效于Discord里@部门）
- 💬 对话流：最近消息时间线，按部门筛选
- 📈 Token仪表盘：各部门消耗柱状图 + 总量趋势

### 技术方向
- Next.js全栈（M2.5全栈能力强）
- 读取Clawdbot session日志 + 调用Clawdbot API
- 部署在同一台Oracle Cloud服务器
- 朝廷红金主题CSS

## ⚠️ 备选方案

**如果对话不够精彩：**
- 补发一条更有争议性的需求细节，比如"要不要加AI部门之间互相打分的功能？"
- 直接@户部问："你觉得工部这个方案成本怎么样？"手动触发讨论
- 跑2-3次选最好的一组

**如果某个部门没响应：**
- 单独@该部门："你怎么看工部的方案？从你的角度有什么建议？"

**如果产出不够视觉化：**
- GUI不需要完全可运行，有清晰的UI截图/原型即可
- 重点是过程（协作讨论），不是最终产品
